## 1. ที่มาและปัญหา

การซื้อขายคอมพิวเตอร์และอุปกรณ์ IT ออนไลน์ โดยเฉพาะของมือสองที่ราคาสูงอย่างการ์ดจอหรือ CPU มักมีปัญหาดังนี้

- ผู้ซื้อโอนเงินไปแล้ว แต่ผู้ขายไม่ส่งของ (โดนโกง)
- ผู้ขายส่งของไปแล้ว แต่ผู้ซื้อไม่ยอมจ่ายหรือกล่าวหาว่าไม่ได้รับของ
- ต้องพึ่งตัวกลางที่เก็บค่าธรรมเนียมสูง และตรวจสอบการทำงานของตัวกลางไม่ได้
- รีวิวผู้ขายถูกปลอมหรือถูกลบได้

## 2. วัตถุประสงค์

1. สร้างตลาดซื้อขายที่**ใครก็ลงขายได้** โดยเงินของผู้ซื้อจะถูก**ล็อกไว้ใน Smart Contract (Escrow)** จนกว่าการซื้อขายจะสำเร็จ
2. ให้ทุกธุรกรรม**โปร่งใสและตรวจสอบย้อนหลังได้** บน Blockchain รวมถึงการกระทำของ Admin ด้วย
3. มีระบบ**คืนเงินอัตโนมัติตามเวลา**และ**ระบบตัดสินข้อพิพาท**
4. มีระบบ**รีวิวผู้ขายที่แก้ไขหรือลบไม่ได้**
5. **ปกป้องข้อมูลส่วนตัว** โดยเก็บที่อยู่จัดส่งไว้นอก Blockchain และให้เห็นเฉพาะคนที่เกี่ยวข้อง
6. มีหน้าเว็บแบบอีคอมเมิร์ซที่ใช้งานง่าย และชำระเงินผ่าน **MetaMask**

### 4.1 หลักการแบ่งข้อมูล

- **Blockchain เป็นแหล่งข้อมูลจริง (Source of Truth) เรื่องเงินและสัญญา** เพราะแก้ไขไม่ได้และไม่ต้องเชื่อใจใคร
- **Supabase เก็บข้อมูลประกอบ** ที่ไม่ควรหรือไม่คุ้มจะเก็บบน chain รวมถึง**สำเนาข้อมูลจาก chain** สำหรับค้นหาและกรองเร็ว ๆ
- **ข้อความยาวเก็บใน Supabase ส่วนบน chain เก็บแค่ hash (keccak256)** หน้าเว็บจึงตรวจได้ว่าข้อมูลใน database ถูกแก้หรือไม่

| ข้อมูล | เก็บที่ | เหตุผล |
|---|---|---|
| ชื่อสินค้า หมวดหมู่ สภาพ **ราคา สต็อก** ผู้ขาย สถานะสินค้า | ⛓ Blockchain | เกี่ยวกับเงินโดยตรง contract ต้องรู้ราคาจริงเพื่อตรวจว่าผู้ซื้อจ่ายครบ |
| คำสั่งซื้อ escrow สถานะ เลขพัสดุ ข้อพิพาท คำตัดสิน | ⛓ Blockchain | หัวใจของระบบ |
| คะแนนรีวิว (ดาว) | ⛓ Blockchain | ต้องแก้ไขไม่ได้ |
| hash ของรายละเอียดสินค้า / ข้อความรีวิว / เหตุผลข้อพิพาท | ⛓ Blockchain | ใช้ตรวจสอบความถูกต้องของข้อมูลใน Supabase |
| รายละเอียดและตารางสเปก | 🗄 Supabase | ถ้าเก็บบน chain จะเสีย gas มาก |
| รูปสินค้า | 🗄 Supabase Storage | อัปโหลดรูปได้จริง |
| **ที่อยู่จัดส่ง ชื่อ และเบอร์โทรผู้ซื้อ** | 🗄 Supabase (ให้เห็นเฉพาะผู้ซื้อกับผู้ขายของคำสั่งซื้อนั้น) | ⚠️ ข้อมูลส่วนตัว **ห้ามเก็บบน chain** เพราะบน chain ทุกคนอ่านได้ |
| โปรไฟล์ (ชื่อร้าน รูปโปรไฟล์) | 🗄 Supabase | |
| ข้อความรีวิว หลักฐานข้อพิพาท (รูป) | 🗄 Supabase | |
| การแจ้งเตือน | 🗄 Supabase | |

### 4.2 การ Sync ข้อมูลจาก Chain

- **Edge Function `sync-chain`** อ่าน Events จาก contract ต่อจากบล็อกล่าสุดที่เคยอ่าน (เก็บไว้ในตาราง `sync_state`) แล้ว upsert ลงตาราง `products`, `orders` และ `reviews`
- ใช้ **pg_cron** เรียกฟังก์ชันนี้ทุก 1 นาที และหน้าเว็บเรียกเพิ่มได้ทันทีหลังธุรกรรมสำเร็จ เพื่อให้ข้อมูลอัปเดตเร็ว
- ตารางที่ sync จาก chain **มีแค่ Edge Function (service role) ที่เขียนได้** ผู้ใช้เขียนตรงไม่ได้ จึงปลอมสถานะคำสั่งซื้อหรือราคาไม่ได้
- ก่อนทำธุรกรรมที่เกี่ยวกับเงิน หน้าเว็บจะ**อ่านราคาและสถานะล่าสุดจาก contract โดยตรง**เสมอ ไม่ใช้ค่าจาก Supabase

### 4.3 การล็อกอิน (Sign in with Ethereum)

1. ผู้ใช้กด Connect MetaMask
2. กด "เข้าสู่ระบบ" แล้ว MetaMask ให้**เซ็นข้อความ** ซึ่งไม่เสีย gas
3. Supabase Auth ตรวจลายเซ็น แล้วออก session ที่ผูกกับ wallet address
4. นโยบาย **RLS (Row Level Security)** ใช้ wallet address จาก session กำหนดว่าใครอ่านหรือเขียนข้อมูลอะไรได้
5. สิทธิ์ Admin ใน Supabase ตรงกับ owner ของ contract (sync มาเก็บในตาราง `admins`)

> ดูสินค้าได้โดยไม่ต้องล็อกอิน แต่ต้องล็อกอินเมื่อจะลงขาย ซื้อ (กรอกที่อยู่) รีวิว หรือดูคำสั่งซื้อ

## 5. ผู้ใช้และสิทธิ์ (ใครก็ขายได้ และ Admin คอยดูแล)

| บทบาท | ใครเป็นได้ | สิ่งที่ทำได้ |
|---|---|---|
| **ผู้เยี่ยมชม** | ทุกคน ไม่ต้องเชื่อม wallet | ดูและค้นหาสินค้า ดูรีวิว |
| **ผู้ซื้อ** | ใครก็ได้ที่เชื่อม MetaMask และล็อกอิน | ใส่ตะกร้า กรอกที่อยู่ ชำระเงิน ยืนยันรับของ ขอคืนเงิน เปิดข้อพิพาท รีวิว ถอนเงินคืน |
| **ผู้ขาย** | ใครก็ได้ที่เชื่อม MetaMask (และไม่ถูกแบน) | ตั้งชื่อร้าน ลงขาย แก้ไข และปิดการขายสินค้าของตัวเอง ดูที่อยู่จัดส่ง แจ้งจัดส่ง รับเงินเมื่อพ้นเวลา ถอนเงิน |
| **Admin** | wallet ที่ deploy contract (โอนสิทธิ์ต่อได้) | ซ่อนสินค้า แบนผู้ขาย ให้ป้าย Verified ตัดสินข้อพิพาท (ดูหลักฐานได้) ตั้งค่าธรรมเนียมและระยะเวลา หยุดระบบชั่วคราว ถอนค่าธรรมเนียม |

> wallet เดียวเป็นได้ทั้งผู้ซื้อและผู้ขาย แต่**ซื้อสินค้าของตัวเองไม่ได้**

**ข้อจำกัดของ Admin (ออกแบบเพื่อความโปร่งใส)**
- **เพิ่มหรือแก้ไขสินค้าของผู้อื่นไม่ได้** ทำได้แค่ซ่อน
- **ลบข้อมูลบน chain ไม่ได้** ประวัติทุกอย่างยังอยู่บน Blockchain
- **ดึงเงิน escrow ของผู้ซื้อไปเองไม่ได้** ถอนได้เฉพาะค่าธรรมเนียมที่สะสมไว้
- ตั้งค่าธรรมเนียมได้**ไม่เกิน 10%**
- **เห็นที่อยู่จัดส่งได้เฉพาะคำสั่งซื้อที่มีข้อพิพาท**
- การกระทำทุกอย่างของ Admin จะปล่อย Event ที่ทุกคนตรวจสอบได้

## 7. ระบบซื้อขายแบบ Escrow

### 7.1 ตะกร้าสินค้าและการชำระเงิน

- ผู้ซื้อเพิ่มสินค้าได้หลายรายการ และ**จากผู้ขายหลายคน**ลงตะกร้าเดียวกัน (ตะกร้าเก็บในเบราว์เซอร์)
- ก่อนชำระเงิน ต้อง**ล็อกอินและเลือกหรือกรอกที่อยู่จัดส่ง**
- กด "ชำระเงิน" แล้ว **MetaMask จะเด้งขึ้นครั้งเดียว** เพื่อจ่ายยอดรวมทั้งตะกร้า
- Contract จะตรวจราคาและสต็อก ตัดสต็อก แล้ว**แยกเป็นคำสั่งซื้อย่อย 1 รายการต่อสินค้า 1 ชนิด**
- ถ้ายอดเงินที่ส่งมาไม่ตรงกับยอดรวม ธุรกรรมจะถูกยกเลิกทั้งหมด
- เมื่อธุรกรรมสำเร็จ หน้าเว็บจะบันทึกที่อยู่จัดส่งลงตาราง `order_shipping` ของแต่ละคำสั่งซื้อ

### 7.2 สถานะคำสั่งซื้อ

```
                ┌──────────── ผู้ขายไม่ส่งของภายใน 3 วัน / ผู้ขายยกเลิกเอง ─────────┐
                │                                                                 ▼
 [ชำระเงินแล้ว] ──ผู้ขายแจ้งจัดส่ง + เลขพัสดุ──▶ [จัดส่งแล้ว]                        [คืนเงินแล้ว]
   (Paid)                                     (Shipped)                           (Refunded)
                                                 │                                    ▲
                     ┌───────────────────────────┼─────────────────────┐              │
                     ▼                           ▼                     ▼              │
          ผู้ซื้อกด "ได้รับของแล้ว"    ผู้ซื้อเงียบเกิน 7 วัน      ผู้ซื้อเปิดข้อพิพาท        │
                     │                ผู้ขายกดรับเงินเอง            (Disputed)          │
                     ▼                           │                     │              │
                [สำเร็จ] ◀───────────────────────┘          Admin ตัดสิน ─┴──────────────┘
               (Completed) ◀───────────────────── (ให้ผู้ขาย)    (ให้ผู้ซื้อ)
                     │
                     ▼

```

| สถานะ | ความหมาย | เงินอยู่ที่ |
|---|---|---|
| Paid | ผู้ซื้อจ่ายแล้ว รอผู้ขายจัดส่ง | ล็อกใน Contract |
| Shipped | ผู้ขายแจ้งจัดส่งพร้อมเลขพัสดุแล้ว | ล็อกใน Contract |
| Disputed | ผู้ซื้อเปิดข้อพิพาท รอ Admin ตัดสิน | ล็อกใน Contract |
| Completed | ซื้อขายสำเร็จ | ผู้ขาย (หักค่าธรรมเนียม) |
| Refunded | คืนเงินแล้ว | ผู้ซื้อ (เต็มจำนวน) |

### 7.3 กฎเรื่องเวลา

| เหตุการณ์ | ค่าเริ่มต้น | ผลเมื่อพ้นเวลา |
|---|---|---|
| ผู้ขายต้องแจ้งจัดส่งภายใน | **3 วัน** หลังชำระเงิน | ผู้ซื้อกดขอคืนเงินได้ |
| ผู้ซื้อต้องยืนยันรับของหรือเปิดข้อพิพาทภายใน | **7 วัน** หลังแจ้งจัดส่ง | ผู้ขายกดรับเงินเองได้ |

- Admin ปรับระยะเวลาได้ เช่น ตั้งเป็น**นาที**ตอนสาธิต
- ระยะเวลาและค่าธรรมเนียม**ถูกบันทึกลงในคำสั่งซื้อตอนจ่ายเงิน** การเปลี่ยนค่าภายหลังจึงไม่กระทบคำสั่งซื้อเดิม
- เมื่อคืนเงิน สต็อกจะถูกคืนให้สินค้า

### 7.4 ข้อพิพาท

- ผู้ซื้อเปิดข้อพิพาทได้เฉพาะตอนที่สถานะเป็น **Shipped** และยังไม่พ้น 7 วัน
- เหตุผลและรูปหลักฐานเก็บใน Supabase ส่วนบน chain เก็บ hash ของเหตุผล
- Admin ดูหลักฐาน แล้วตัดสินได้ 2 แบบ คือ **คืนเงินให้ผู้ซื้อ** หรือ **จ่ายเงินให้ผู้ขาย**
- คำตัดสินพร้อมเหตุผลถูกบันทึกเป็น Event ซึ่งตรวจสอบได้

### 7.5 ค่าธรรมเนียมแพลตฟอร์ม

- ค่าเริ่มต้น **2%** หักจากเงินที่ผู้ขายได้รับ**เมื่อซื้อขายสำเร็จเท่านั้น**
- กรณีคืนเงิน ผู้ซื้อได้คืน**เต็มจำนวน** และไม่มีค่าธรรมเนียม
- Admin ปรับได้ระหว่าง 0–10%

### 7.6 การถอนเงิน (Pull Payment)

เพื่อความปลอดภัย Contract **จะไม่โอนเงินออกไปเองทันที** แต่จะบันทึกยอดเงินที่แต่ละคนถอนได้ไว้ก่อน แล้วผู้ใช้กดปุ่ม **"ถอนเงิน"** เพื่อรับ ETH เข้า wallet

- ผู้ขาย: ได้รับเงินค่าสินค้าหลังหักค่าธรรมเนียม
- ผู้ซื้อ: ได้รับเงินคืน
- Admin: ถอนค่าธรรมเนียมสะสมได้ผ่านฟังก์ชันแยกต่างหาก

## 8. รีวิวและ Verified Seller

**รีวิว**
- ผู้ซื้อรีวิวได้ **1 ครั้งต่อคำสั่งซื้อที่สำเร็จ**
- คะแนน 1–5 ดาวและ hash ของความเห็นเก็บ**บน chain** ส่วนข้อความความเห็นเก็บใน Supabase
- รีวิว**แก้ไขหรือลบไม่ได้** ทั้งผู้ขายและ Admin ถ้าข้อความใน Supabase ถูกแก้ หน้าเว็บจะตรวจเจอจาก hash
- หน้าเว็บแสดงคะแนนเฉลี่ยและจำนวนรีวิวของผู้ขาย

**Verified Seller**
- Admin ให้หรือถอนป้าย **✔ Verified** ให้ผู้ขายได้
- ป้ายนี้ไม่บังคับ ผู้ขายที่ไม่มีป้ายก็ยังขายได้ตามปกติ

### 11.1 ส่วนที่มีทุกหน้า

## 12. การทดสอบ

### 12.1 Smart Contract (Hardhat Unit Test)
- ลงขาย แก้ไข และปิดการขายสินค้า รวมถึงตรวจสิทธิ์ว่าแก้ไขสินค้าของคนอื่นไม่ได้
- Checkout หลายรายการจากผู้ขายหลายคน · ยอดเงินไม่ตรงต้องถูกปฏิเสธ · สต็อกไม่พอ · ห้ามซื้อสินค้าของตัวเอง
- แก้ราคาหลังมีคำสั่งซื้อแล้ว ต้องไม่กระทบคำสั่งซื้อเดิม
- Flow ปกติ: Paid → Shipped → Completed และตรวจว่าค่าธรรมเนียมถูกหักถูกต้อง
- คืนเงินเมื่อผู้ขายไม่ส่งของตามเวลา โดยใช้การเลื่อนเวลาของ Hardhat
- ผู้ขายรับเงินเองเมื่อผู้ซื้อไม่ยืนยันตามเวลา
- ข้อพิพาท: Admin ตัดสินให้ผู้ซื้อ และตัดสินให้ผู้ขาย
- รีวิว: รีวิวซ้ำไม่ได้ และรีวิวคำสั่งซื้อที่ยังไม่สำเร็จไม่ได้
- Admin: ซ่อนสินค้า แบนผู้ขาย ตั้งค่าธรรมเนียมเกิน 10% ไม่ได้ · ผู้ใช้ที่ไม่ใช่ Admin เรียกใช้ไม่ได้
- Pause: ซื้อไม่ได้ แต่ยังคืนเงินและถอนเงินได้
- ถอนเงิน: ยอดถูกต้อง และถอนซ้ำไม่ได้

### 12.2 Supabase
- ทดสอบ RLS: ผู้ใช้อื่นอ่านที่อยู่จัดส่งของคำสั่งซื้อที่ไม่เกี่ยวข้องไม่ได้ · ผู้ใช้เขียนตาราง `products` / `orders` ตรงไม่ได้ · ผู้ขายแก้ `product_details` ของคนอื่นไม่ได้
- ทดสอบ `sync-chain`: ข้อมูลใน Supabase ตรงกับ chain หลังทำธุรกรรม และรันซ้ำแล้วไม่เกิดข้อมูลซ้ำ
- ใช้ Supabase Advisors ตรวจความปลอดภัยและประสิทธิภาพ

### 12.3 ทดสอบบน Hoodi (Manual)
ใช้ MetaMask **3 บัญชี** คือ Admin, ผู้ขาย และผู้ซื้อ แล้วทดลองทุก Flow บนหน้าเว็บ และตรวจผลบน hoodi.etherscan.io

## 13. การติดตั้งและ Deploy

1. เพิ่ม Hoodi Testnet ใน MetaMask และขอ ETH ทดสอบจาก Hoodi Faucet
2. **Contract:** สร้าง `contracts/.env` ใส่ RPC URL และ Private Key ของ**บัญชีทดสอบเท่านั้น** (ห้ามใช้บัญชีที่มีเงินจริง)
3. `npx hardhat test` แล้ว deploy ด้วย `npx hardhat run scripts/deploy.ts --network hoodi`
4. สคริปต์ deploy คัดลอก ABI และ Contract Address ไปที่ `web/src/contracts/` ให้อัตโนมัติ
5. Verify Contract บน hoodi.etherscan.io (ทำหรือไม่ก็ได้)
6. **Supabase:** สร้างโปรเจกต์ `chainpc` → รัน migrations (ตาราง, RLS, buckets) → เปิด Web3 Auth (Ethereum) → deploy Edge Function `sync-chain` และตั้ง secret (RPC URL, Contract Address, block เริ่มต้น) → ตั้ง pg_cron
7. **Web:** สร้าง `web/.env` ใส่ `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`, `VITE_HOODI_RPC_URL` แล้วรัน `npm run dev`
8. (ทำหรือไม่ก็ได้) รันสคริปต์ seed เพื่อลงสินค้าตัวอย่างสำหรับสาธิต
9. (ทำหรือไม่ก็ได้) Deploy เว็บขึ้น Vercel หรือ Netlify

> ⚠️ ห้าม commit ไฟล์ `.env`, Private Key และ Supabase service role key ขึ้น GitHub

## 15. สิ่งที่ไม่อยู่ในขอบเขตงาน (Out of Scope)

- ใช้งานบน Mainnet หรือใช้เงินจริง

- ระบบแชตระหว่างผู้ซื้อกับผู้ขาย
- แจ้งเตือนทางอีเมล / LINE (มีแค่แจ้งเตือนภายในเว็บ)
- ยืนยันตัวตน (KYC) และล็อกอินด้วยอีเมล/รหัสผ่าน
- แอปมือถือ (มีแค่เว็บแบบ Responsive)
- เก็บไฟล์บน IPFS
