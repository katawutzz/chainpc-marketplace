| Supabase Security Advisor | `npx supabase db advisors --remote` | ✅ ไม่มีปัญหาด้านตาราง/RLS (เหลือ 1 คำเตือนเรื่อง Leaked Password Protection ซึ่งไม่เกี่ยว เพราะไม่ได้ใช้ล็อกอินด้วยรหัสผ่าน) |

### สิ่งที่ `npm run healthcheck` ตรวจ
- เงินใน contract ≥ escrow + ค่าธรรมเนียม (contract จ่ายทุกคนได้ครบ)
- จำนวนสินค้า/คำสั่งซื้อใน Supabase ตรงกับบน chain และ cron sync ยังทำงาน
- RLS: คนที่ไม่ได้ล็อกอิน **อ่าน**ที่อยู่จัดส่ง / สมุดที่อยู่ / รายละเอียดแจ้งปัญหา / แจ้งเตือน **ไม่ได้**
  และ**เขียน**สินค้า / คำสั่งซื้อ / รีวิว ปลอม **ไม่ได้**

## 3. ปัญหาที่พบระหว่างพัฒนาและวิธีแก้

| ปัญหา | สาเหตุ | วิธีแก้ |
|---|---|---|
| Compile ใน Remix ไม่ผ่าน "Stack too deep" | `checkout()` มีตัวแปรเยอะเกิน stack ของ EVM | แยกส่วนสร้างคำสั่งซื้อเป็น `_placeOrder()` — compile ได้โดยไม่ต้องใช้ viaIR |
| Edge Function เขียนตารางไม่ได้ (permission denied) | โปรเจกต์ไม่ได้เปิด "Grant API access automatically" | migration `service_role_grants` |
| Security Advisor เตือนฟังก์ชัน SECURITY DEFINER เปิดผ่าน API | `current_wallet()` / `is_admin()` อยู่ใน schema public | ย้ายไป schema `app_private` |
| การรีวิวต้องยืนยันใน MetaMask | รีวิวเดิมเก็บบน chain | ย้ายรีวิวไป Supabase (ดู SCOPE ข้อ 8) |
| ผู้ใช้ไม่เข้าใจคำว่า "ข้อพิพาท" | ศัพท์กฎหมาย | เปลี่ยนเป็น "แจ้งปัญหา" บนหน้าเว็บ |
